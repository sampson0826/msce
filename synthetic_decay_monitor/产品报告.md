## 一、这是什么

一个 LLM "递归稳定性"评估系统。现有所有 LLM 评测（MMLU、HumanEval、Chatbot Arena）只测单次输出质量——没有人在测**模型在自主循环中能撑多久**。我们填补这个空白。

**核心指标：β（衰减率）**——模型递归生成时，约束质量每代丢失的速率。β 越高，模型在 agent loop 中退化越快。

## 二、已发现的事实

跨 4 个模型家族的递归生成实验（12 seeds × 3 代）：

| 模型 | β | 家族 |
|------|:----:|------|
| Qwen2.5-7B | 0.2865 | Qwen |
| Claude Opus 4.6 | 0.2971 | Claude |
| Claude Sonnet 4.6 | 0.3106 | Claude |
| Claude Haiku 4.5 | 0.3107 | Claude |

**关键发现：**
- β ~0.30 跨 4 模型高度一致，β 是模型家族常数（Claude 家族范围 0.0136 < 0.02 阈值，PASS）
- 约束吸引子坍缩：均值 ||Π|| 稳定，但方差 C_div 每代坍缩 4.5×（λ_C = 0.2973/gen）
- 三种执行者退化模式：E-I（逻辑断裂，α=0.40）、E-II（风格均质化，α=0.20）、E-III（事实侵蚀，α=0.08）
- 纯文本特征提取可达 75% 准确率，无需 GPU

## 四、产品路线图

### Phase A：统一实验框架 ✅（2026-05-12 完成）

**产出：**
- `provider_adapter.py` — 统一 API 后端（QuickRouter/OpenAI/本地），告别硬编码 API key
- `experiment_config.py` — 可复现实验配置，6 个预设，JSON 持久化
- `experiment_runner.py` — 一条命令跑完整实验：生成→分析→诊断→报告→跨模型对比
- `pyproject.toml` — 项目配置
- 删除 3 个临时脚本，功能全部整合

**用法：**
```bash
python -m synthetic_decay_monitor.experiment_runner --preset opus
python -m synthetic_decay_monitor.experiment_runner --model claude-sonnet-4-6 --provider quickrouter --compare haiku_lineage.jsonl opus_lineage.jsonl
```

### Phase B：数据层加固（预计 2 周）← 下一步

- 统一数据目录，集中 3 处分散的实验数据
- RealLineageDataset 标准化加载/验证/导出

### Phase C：P3 严格检验 + 第三方模型家族（预计 4 周）

- 窗口 1 GPU 产出逐维 π 分量 → P3 严格检验（这是论文最关键的缺失数据）

- Llama 3 实验（第四个模型家族）
- 不同 temperature（0.0/0.5/1.0）下 β 稳健性
- n=100 seeds 统计稳定性验证
- **产出：arXiv 论文核心数据**

### Phase D：SaaS API（预计 6 周）

- FastAPI 后端（已有 server.py 基础）
- 异步任务队列（Celery + Redis）
- 用户管理 + API key + 用量统计
- Stripe 支付集成
- React 前端仪表盘（交互式 β 对比图）

### Phase E：监控集成（预计 6 周）

- `pip install decay-monitor` → `monitor.watch(model_output)` 实时 C_div
- LangChain callback：agent loop 中自动退化检测
- Webhook 告警：C_div 低于阈值 → Slack/email 通知
- 自动切换：退化检测 → 切换到备选模型

## 五、商业模型

### 价值主张

**现有 LLM 评测告诉你模型"答对多少题"。我们告诉你模型"在自主循环中能撑多久"。**

这对于 AI agent 开发者是刚需——选模型不能只看 benchmark 分数，要看它在自主循环中的稳定性。

| 层级 | 客户 | 痛点 | 产品 |
|------|------|------|------|

## 七、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |

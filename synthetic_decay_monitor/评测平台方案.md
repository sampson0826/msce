# DecayMonitor — LLM 递归稳定性评测平台方案

**版本：** v1.0 / 2026-05-12
**定位：** 评测 LLM 在自主循环中"能撑多久"的独立第三方平台

---

## 一、产品概述

### 1.1 现有 LLM 评测的盲区

当前所有主流评测体系——MMLU（知识）、HumanEval（代码）、Chatbot Arena（人类偏好）、HELM（多维度）——测的都是**单次输入→输出的质量**。

但真实世界的 AI agent 不是单次调用。一个 AutoGPT 任务需要 10-50 次模型调用，每次调用会读到自己前一轮的输出。模型在**递归读取自己的输出时会退化**，而这个退化速度，现有所有评测都看不到。

### 1.2 我们的定位

**DecayMonitor 是在 LLM 评测矩阵中新增一个维度：递归稳定性（Recursive Stability）。**

| 评测体系 | 测什么 | 怎么测 |
|----------|------|------|
| MMLU | 知识覆盖 | 单选题正确率 |
| HumanEval | 代码生成 | 单次生成通过率 |
| Chatbot Arena | 人类偏好 | 众包投票 ELO |
| HELM | 多维度 | 42 个场景 + 7 个指标 |
| **DecayMonitor** | **递归稳定性** | **β 衰减率 × 6 能力维度** |

### 1.3 核心指标：β（衰减率）

**β = 模型在递归生成中，每代丢失的约束质量比例。**

- β = 0.10：10 代后保留 0.9^10 ≈ 35% 质量 → 稳定型
- β = 0.31：10 代后保留 0.69^10 ≈ 2% 质量 → 退化型
- β = 0.50：3 代后已无法使用 → 不适合任何 agent 场景

β 可以直接回答 benchmark 回答不了的问题："这个模型在我的 agent loop 里能撑几轮。"

**跨能力维度分解：** 同一个模型，math_reasoning β=0.40（退化快），factual_knowledge β=0.08（退化慢）。这意味着训练数据在数学领域缺乏自我纠错样本——这对模型训练团队是 actionable insight。

## 二、算法原理

整个评测管线分为三步。全部在 CPU 上完成，不需要 GPU。

### 2.1 文本特征提取（纯规则，零依赖）

对每个样本提取 8 个表面统计特征，按执行者类型分为三组：

**E-I 公理级（逻辑/推理链）：**

| 特征 | 计算方式 | 退化信号 |
|------|---------|---------|
| `ei_logic_density` | 逻辑连接词出现次数 / 总 token 数 | 推理链断裂时下降 |
| `ei_syntax_cv` | 句子长度变异系数（std/mean） | 句子结构崩坏时升高 |

逻辑连接词库内置 35+ 英文（therefore/because/thus/hence/nevertheless……）+ 15+ 中文（因此/所以/然而/从而/故/则……）。

**E-II 标度级（风格/表达）：**

| 特征 | 计算方式 | 退化信号 |
|------|---------|---------|
| `eii_bigram_repetition` | 重复 bigram 数 / (总 bigram 数 + 1) | 车轱辘话增多时上升 |
| `eii_unique_word_ratio` | 唯一词数 / 总词数 | 词汇多样性下降时下降 |
| `eii_filler_ratio` | 高频填充词（the/a/is/of/this/……）占比 | 废话比例升高时上升 |
| `eii_truncation_ratio` | 被截断的长词（>7 字符）比例 | 输出不完整时升高 |

**E-III 边界级（事实/格式）：**

| 特征 | 计算方式 | 退化信号 |
|------|---------|---------|
| `eiii_proper_case_ratio` | 首字母大写单词 / 总词数（英文）/ 专名标注率（中文） | 大小写/标注规约丢失时下降 |
| `eiii_number_integrity` | 保持原样的数字个数 / 总数字个数 | 数字被篡改/四舍五入时下降 |

**自适应分块：** 长文本（>300 tokens）自动切片到 Goldilocks 区（80-200 tokens），取各块特征均值，避免长文本饱和效应。

**语言自动检测：** 中/英文使用各自独立的连接词库和分词逻辑。

### 2.2 特征 → 约束状态（S_n）

8 个特征经加权映射为 5 维约束状态：

```
sigma_syntax  = 0.65 × ei_logic_density + 0.35 × ei_syntax_cv       [E-I]
sigma_style   = unique_word_ratio × (1 - 0.5×bigram_rep - 0.3×trunc - 0.2×filler)  [E-II]
sigma_fact    = 0.55 × proper_case_ratio + 0.45 × number_integrity   [E-III]
sigma_coherence = 0.55 × ei_logic_density + 0.45 × (1 - bigram_rep)
sigma_safety  = 0.5 (中性)

S_n = (sigma_fact + sigma_syntax + sigma_style + sigma_safety + sigma_coherence) / 5
```

S_n ∈ [0, 1]。每个样本一个 S_n，同代同能力维度的样本取均值得到该代该能力的约束基线。

**权重来源：** 各权重（0.65/0.35、0.55/0.45 等）经 4 模型（Qwen/Sonnet/Haiku/Opus）实验校准，与 LLM judge（Claude）在该维度的 Spearman 相关性成比例——相关性高的特征权重高。E-I 相关性 0.93，E-II 0.98，E-III 0.27——所以 E-III 维度权重整体偏低，优先使用 LLM judge（如可用）。

### 2.3 S_n 代际序列 → β 拟合

对每个能力维度，跨代追踪 S_n 序列，拟合指数衰减模型：

```
S_n = S_0 × (1 - β)^n
log(S_n / S_0) = n × log(1 - β)
```

用最小二乘线性回归估计斜率 k = log(1-β)，反推 β = 1 - e^k。

β 钳制在 [0.03, 0.55] 内（低于 0.03 为噪声，高于 0.55 意味着 3 代内完全坍缩——实际中极少出现）。

**全局 β** 为各能力维度 β 的算术平均，作为模型的"递归稳定性总分"。

### 2.4 退化状态分类

| S_n 范围 | 状态 | 含义 |
|----------|------|------|
| > 0.80 | healthy | 约束结构完整 |
| 0.50-0.80 | degrading | 开始退化 |
| 0.30-0.50 | critical | 接近坍缩 |
| < 0.30 | collapsed | 已坍缩 |

预测坍缩代数：当 S_n < 0.30 时判定为坍缩。基于拟合曲线 S_n = (1-β)^n，求解 n = log(0.30) / log(1-β)。

### 2.5 执行者类型诊断

从跨代 σ 变化率 + 文本特征指纹，自动判断退化主要由哪种执行者失效导致：

- **E-I 退化**：逻辑连接词丢失 + 句法 CV 上升 → 推理链断裂 → 干预：加 chain-of-thought 校准
- **E-II 退化**：bigram 重复上升 + 词汇多样性下降 → 风格坍缩 → 干预：提高 temperature 或换模型
- **E-III 退化**：大小写/数字规约丢失 → 边界侵蚀 → 干预：加输出格式约束

## 三、技术架构

### 3.1 系统总览

```
┌─────────────────────────────────────────────────────┐
│                   decaymonitor.ai                     │
├──────────────────┬──────────────────────────────────┤
│   前端 (React)    │   后端 (FastAPI)                   │
│   β 排行榜        │   POST /eval → 异步评测             │
│   模型详情页       │   GET /leaderboard → β 数据         │
│   6 维衰减曲线     │   GET /model/{id} → 完整报告         │
├──────────────────┼──────────────────────────────────┤
│         评测引擎 (ExperimentRunner)                    │
│   ProviderAdapter → 12 seeds × 3 gen → DecayEngine     │
│   纯文本特征模式（CPU）- 秒级完成                         │
│   可选 LLM Judge 模式（GPU）- 更高 E-III 精度            │
├──────────────────┼──────────────────────────────────┤
│   定时调度 (Celery) │   数据层 (PostgreSQL + S3)       │
│   每周一自动评测     │   lineage JSONL 归档              │
│   新模型上线即测     │   β 历史曲线                      │
│   模型更新复测       │   实验元数据（API 成本/时间）        │
└──────────────────┴──────────────────────────────────┘
```

### 3.2 评测流水线

每周自动运行：

1. **模型发现**：从 providers.json 读取待评测模型列表（手动维护 + API 自动发现）
2. **调度**：Celery 分发评测任务到 worker（每个模型一个独立任务）
3. **生成**：ExperimentRunner.run_generation() — 12 seeds × 3 gens → JSONL
4. **分析**：DecayEngine.run_all_capabilities() → 6 能力 β + 全体 β
5. **存储**：结果入库（PostgreSQL），JSONL 归档
6. **发布**：更新排行榜缓存（Redis），刷新前端

单个模型评测耗时：12 seeds × 3 gens × 0.5s sleep ≈ 18 秒（API 调用时间另计，取决于模型延迟）。

### 3.3 多 Provider 支持（已有）

通过 ProviderAdapter 抽象层，当前支持：

| Provider | 覆盖模型 |
|----------|---------|
| QuickRouter | Claude Sonnet/Opus/Haiku |
| OpenAI | GPT-4o, GPT-4.1, o3-mini |
| Together AI | Llama 3, Mixtral, DeepSeek |
| DeepSeek 官方 | DeepSeek-V3, DeepSeek-R1 |
| Local（vLLM 兼容） | 自部署开源模型 |

新增 provider 只需实现 `ProviderAdapter.generate()` 方法。

### 3.4 评测模式对比

| | 标准模式（免费榜） | 深度模式（付费） |
|------|:---:|:---:|
| seeds 数 | 12 | 100 |
| 代数 | 3 | 3-5 |
| 特征提取 | 纯文本（CPU） | 纯文本 + LLM Judge |
| 执行者诊断 | 基本 | 全 E-I/E-II/E-III 分解 |
| 训练建议 | 无 | 跨能力 β 差异 → 数据盲区 |
| 完成时间 | < 2 分钟 | < 10 分钟 |
| 费用 | $0.50-2（API 成本） | $5-20（API 成本） |

## 五、商业模型

### 5.1 价值主张

**"现有的 LLM 评测告诉你模型能答对多少题。我们告诉你模型在自主循环中能撑多久。"**

对于 AI agent 开发者，选模型不能只看 benchmark 分数——benchmark 第一的模型可能在你的 agent loop 里 10 轮就退化到不可用。β 是多一个决策维度。

### 5.2 收入来源（三档）

#### 免费档：公开排行榜

- 所有公开模型的 β 排行榜（12 seeds 模式）
- 模型详情页 + 6 维衰减曲线
- API 免费调用（限 50 次/天）
- **目的：引流 + 建立权威**

#### Pro 档：闭门评测（$499/次）

**目标客户：** 模型厂商在发布前想私下测试自己的模型

- 完全私密：结果不上榜
- n=100 seeds 全量评测
- E-I/E-II/E-III 执行者深度诊断
- 与竞品模型的 β 匿名对比
- 交付：PDF 报告 + 原始数据 CSV/JSONL

**为什么值 $499：** 模型厂商在发布前已经在花远高于此的 API 费用做内部评测。β 报告提供一个他们自己没有的视角（递归稳定性），且一次购买即可。

#### Enterprise 档：持续评测（$2,999/月）

**目标客户：** LLM 训练团队每次出新 checkpoint 都要测

- 无限次评测（每 checkpoint 一次）
- n=100 seeds × 5 gens 全量评测
- 跨 checkpoint β 历史曲线—追踪训练对稳定性的影响
- 训练数据诊断：β 在 math_reasoning 上 0.40 而在 factual 上 0.08 → 数学训练数据缺少自我纠错对
- 专属 API endpoint + Slack 集成
- 季度电话诊断（我们的研究人员解读 β 变化）

**为什么值 $2,999/月：** 训练团队每月几十万的算力成本。β 跨能力分布的差异能直接指出训练数据的盲区——这是现有评测做不到的。一个 actionable insight 的价值远超 $2,999。

### 5.5 竞争优势（为什么别人不做）

1. **先发优势 + 科学护城河**：arXiv 论文 + 跨 4 家族数据 + 理论框架（约束吸引子坍缩）——不是只测了一个分数，是背后有一套可验证的因果理论。抄评测容易，抄理论难。

2. **CPU-only 评测**：纯文本特征提取不需要 GPU。Chatbot Arena 需要大规模人类投票，我们的全流程自动化。边际成本接近零。

3. **多 Provider 抽象层**：新增模型只需一行配置。别人要支持新 provider 得从头写。我们已经在 3+ 后端验证过。

4. **评测维度不可替代**：MMLU 测知识覆盖面，我们测循环稳定性。这两个维度是正交的——加分项，不是替代项。如果行业接受"递归稳定性"是新维度，定义者天然有权威。

| β 在 n=100 时不显著 | 中 | 高 | 先做 n=100，结果不好不投论文 |
| 没有模型厂商愿意付费评测 | 中 | 中 | 免费榜先建权威 → 付费是自然延伸 |
| 大模型公司自己做 | 高 | 低 | 他们只能测自己，我们跨模型视角不可替代 |
| 竞品出现 | 中 | 中 | 论文+开源建立先发优势，6 个月窗口 |
| 纯文本特征被质疑准确性 | 低 | 中 | 论文中公布与 LLM judge 的 Spearman 对比数据 |

How Poly Network Was Exploited — Constraint View

Protocol Architecture

EthCrossChainManager.verifyHeaderAndExecuteTx()

1. Verify cross-chain message signature (L1 constraint)

2. Decode payload from verified message

3. Execute payload on target chain → can call putCurEpochConPubKeyBytes() to change keepers

The missing L1→L2 executor: nothing prevents payload execution from modifying the verification infrastructure.

Attack Path

1. Attacker crafts a cross-chain message with a payload that calls putCurEpochConPubKeyBytes

2. Verification passes — the message format is valid

3. Payload executes → keeper keys replaced with attacker's keys

4. All future verification now passes for attacker → full drain

The dark zone is at the verification/access boundary — where verification succeeds but the access wall has a hole.
